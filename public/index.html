사용 방법

4단계면 AI 애플리케이션 Observability를 직접 확인할 수 있습니다.

Pipeline 선택

None(단순 호출), RAG(문서 검색), Agentic(AI Agent) 중 하나를 고릅니다.

여행지 입력 & 실행

도시 이름을 입력하고 추천 받기를 누릅니다. 응답 언어는 한국어/English 중 선택할 수 있습니다.

Dynatrace에서 Trace 확인

Distributed Tracing에서 서비스 travel-advisor를 선택하면 LLM Span과 Token 정보를 볼 수 있습니다. Users & Sessions에서 브라우저 요청을 선택하면 연결된 Backend Trace로 이동합니다.

참고: RUM Session · Trace

AI Observability 대시보드

AI Observability 앱 또는 Dashboard에서 Model별 요청 수, 지연 시간, Token 사용량 추이를 확인합니다.

참고: 대시보드 · Dynatrace App

Pipeline 비교

같은 질문이라도 Pipeline에 따라 내부 동작과 Dynatrace에 보이는 Trace 구조가 달라집니다.

Pipeline동작 방식LLM 호출 수Dynatrace에서 볼 포인트
None 프롬프트를 LLM에 한 번 전달해 답변 생성 1회 LLM Span 1개 · 응답 시간 · 입력/출력 Token
RAG 여행 문서(destinations/*.html)를 Embedding → FAISS Vector 검색 → 검색 결과를 근거로 LLM 답변 1회 + Embedding Retriever/Embedding 단계와 LLM 단계의 시간 비중, 검색된 Context가 답변에 준 영향
Agentic LangChain AI Agent가 valid_city, travel_advice 등 Tool을 선택·반복 실행 여러 번 (가변) Agent Workflow → Tool → LLM으로 이어지는 다단계 Trace, 반복 횟수와 누적 Token

데모 시나리오 팁

고객 앞에서 보여주기 좋은 장면들입니다.

① RAG 품질 이슈 추적

Sydney를 None과 RAG로 각각 실행해 보세요. RAG 문서에 일부러 잘못된 정보(“인구 237명, 낙타로만 이동”)가 들어 있어 답변이 달라집니다. Trace에서 검색된 Context를 확인해 원인을 찾는 과정을 시연합니다.

② Agent 비용 · 지연 분석

Agentic으로 실행하면 LLM이 여러 번 호출됩니다. None 대비 누적 Token과 응답 시간이 얼마나 늘어나는지 Distributed Tracing에서 비교합니다.

③ 오류 · 장애 가시화

LLM 인증 오류나 Guardrail 차단이 발생하면 해당 Span이 오류로 표시되고 예외 메시지가 함께 기록됩니다. Davis AI가 이상 징후로 탐지하는 흐름을 설명합니다.
