PART 1

Agent 동작 원리 한눈에 보기

여행사 창구 직원(Agent)이 필요한 도구(Tool)를 스스로 골라 쓰며 답을 만들고, Dynatrace는 그 모든 과정을 한 건의 Trace로 기록합니다.

flowchart LR U[사용자
Web Browser] -->|여행지 요청| A[travel-advisor
FastAPI] A --> P{Pipeline} P -->|None| L1[LLM 1회 호출] P -->|RAG| R[FAISS 문서 검색] --> L2[LLM 답변] P -->|Agentic| AG[travel-advisor-agent] AG --> T1[valid_city Tool] AG --> T2[travel_advice Tool] A -. OpenTelemetry .-> DT[Dynatrace]

None은 LLM을 한 번 호출하고, RAG는 문서를 먼저 검색한 뒤 호출합니다. Agentic은 LLM이 스스로 판단해 여러 번 호출되는 구조라서 보이지 않으면 비용과 지연을 통제할 수 없습니다.

Agent 구성 요소

Agent(pipeline/agentic.py)는 도구, 행동 규칙, 반복 실행기 세 가지로 이루어집니다.

① 도구 (Tools)

Agent가 쓸 수 있는 함수입니다. Agent는 각 함수의 설명(docstring)을 읽고 어떤 도구를 쓸지 고릅니다. 도구 안에서도 LLM이 다시 호출됩니다.

Tool역할
valid_city입력한 여행지가 실제 도시인지 확인
travel_advice여행 조언 생성
movie_quote영화 대사 (Agent가 엉뚱한 도구를 고르는지 확인하는 미끼)
python
@tool
def valid_city(city: str) -> bool:
    """Returns if the input is a valid city"""   # ← Agent가 읽는 설명
    response = get_model().chat(f"Is {city} a city? respond only with yes or no.")
    return response == "yes"

② 행동 규칙 (ReAct Prompt)

LLM에게 "생각 → 도구 선택 → 결과 확인"을 반복하고, 정해진 JSON 형식으로만 답하도록 지시합니다. 이 방식을 ReAct(Reason + Act) 패턴이라고 합니다.

text
Thought: 무엇을 할지 생각
Action: {"action": "valid_city", "action_input": {"city": "Tokyo"}}
Observation: (도구 실행 결과)
... 반복 ...
Action: {"action": "Final Answer", "action_input": "최종 답변"}

③ 반복 실행기 (AgentExecutor)

python
AgentExecutor(agent=agent, tools=tools,
              handle_parsing_errors=True,   # 형식이 틀리면 다시 시도
              max_iterations=10)            # 무한 루프 방지

④ Observability 래퍼

Agent 실행 전체를 OpenTelemetry GenAI 표준 속성으로 표시해, Dynatrace AI Observability의 Agents topology에 Agent로 나타나게 합니다.

python
@traceloop_agent(name="travel-advisor-agent")
def _invoke_agent(self, model, task):
    span = trace.get_current_span()
    span.set_attribute("gen_ai.operation.name", "invoke_agent")
    span.set_attribute("gen_ai.agent.name", "travel-advisor-agent")
    return self.agent_executor.invoke({"input": task})

요청 한 건의 흐름

"도쿄"를 Agentic으로 요청하면 사용자 요청은 1건이지만 LLM은 약 5번 호출됩니다. None보다 응답이 느리고 Token 비용이 3~5배 드는 이유입니다.

sequenceDiagram participant U as 사용자 participant A as Agent participant L as Claude (LLM) participant T as Tools U->>A: 도쿄 A->>L: ① 무엇을 할까? L-->>A: valid_city 사용 A->>T: valid_city(Tokyo) T->>L: ② 도시인가? L-->>T: yes A->>L: ③ 다음 행동은? L-->>A: travel_advice 사용 A->>T: travel_advice(Tokyo) T->>L: ④ 여행 조언 생성 A->>L: ⑤ 최종 답변 정리 (한국어) A-->>U: 답변

Dynatrace에서 보이는 모습

모든 단계가 하나의 Trace로 연결되고, LLM·Tool Span에는 gen_ai.agent.name이 붙어 "이 Agent가 요청 한 건에 Token을 얼마나 썼는지", "어느 단계가 느렸는지"를 바로 볼 수 있습니다.

trace
/api/v1/completion                     ← FastAPI 요청
 └ travel_answer_generator.workflow
    └ travel-advisor-agent.agent       ← invoke_agent (Agents topology의 Agent 노드)
       └ AgentExecutor.workflow
          ├ ChatAnthropic.chat          ← Agent 판단 (Token · 지연)
          ├ valid_city.tool             ← execute_tool
          │  └ anthropic.chat
          ├ ChatAnthropic.chat
          ├ travel_advice.tool          ← execute_tool
          │  └ anthropic.chat
          └ ChatAnthropic.chat          ← Final Answer
확인 위치: AI Observability → Agents topology에서 travel-advisor → travel-advisor-agent → Anthropic → claude-haiku-4-5 연결을, Distributed Tracing에서 위 Span 트리를 확인합니다.
PART 2 · TRACELOOP(OPENLLMETRY) 적용 가이드

1. 개요

Python·Node.js AI 앱에 코드 2줄(import와 Traceloop.init)만 추가하면 LLM 호출, RAG, Agent 흐름이 OpenTelemetry로 Dynatrace에 수집됩니다.

  • Traceloop OpenLLMetry: OpenTelemetry 기반 오픈소스 SDK입니다. LLM SDK와 LangChain 같은 프레임워크를 자동 계측해 gen_ai.* 속성(Model, Token, 응답 시간)을 Span에 기록합니다.
  • Dynatrace: OTLP/HTTP Endpoint(/api/v2/otlp)로 데이터를 받아 Grail에 저장하고, AI Observability 앱·Distributed Tracing·Davis AI로 분석합니다.
flowchart LR A[AI 앱
Python · Node.js] -->|LLM 호출| B[LLM Provider
Claude · Bedrock · OpenAI] A -->|자동 계측| C[Traceloop SDK] C -->|OTLP/HTTP| D[Dynatrace
/api/v2/otlp] D --> E[AI Observability
Distributed Tracing · Davis AI]

2. 사전 준비 체크리스트

Endpoint 형식과 Python 버전이 가장 많이 막히는 부분입니다.

  • Dynatrace SaaS(DPS): Traces·Metrics powered by Grail, Log Analytics 활성화
  • API Token scope 3개: openTelemetryTrace.ingest, metrics.ingest, logs.ingest
  • OTLP Endpoint: https://<tenant-id>.live.dynatrace.com/api/v2/otlp (.apps. 아님, 끝에 / 없음)
  • Python 3.10 이상: traceloop-sdk 0.50.x는 Python 3.9에 설치되지 않음 (Node.js는 3-1장)
  • LLM SDK 버전: anthropic, boto3, openai, langchain 등이 SDK 지원 범위인지 확인
  • 네트워크: 앱 실행 환경에서 Dynatrace Endpoint로 HTTPS(443) 아웃바운드 허용

3. 5분 적용 (Python)

초기화는 LLM SDK나 LangChain을 import하기 전에 한 번만 호출해야 자동 계측이 걸립니다.

① 설치

bash
pip install traceloop-sdk "wrapt<2"

② 환경 변수

bash
export DT_ENDPOINT=https://<tenant-id>.live.dynatrace.com   # 끝에 / 없이
export DT_TOKEN=dt0c01.xxxx                                  # scope 3개
export OTEL_EXPORTER_OTLP_METRICS_TEMPORALITY_PREFERENCE=delta  # Dynatrace는 delta 메트릭 수신
export TRACELOOP_TELEMETRY=false                             # Traceloop 사용 통계 전송 끄기

③ 초기화 코드 (앱 시작 파일 맨 위)

python
import os
from traceloop.sdk import Traceloop

Traceloop.init(
    app_name="my-ai-app",                                     # Dynatrace 서비스 이름
    api_endpoint=os.environ["DT_ENDPOINT"] + "/api/v2/otlp",  # https:// 로 시작해야 HTTP 전송
    headers={"Authorization": f"Api-Token {os.environ['DT_TOKEN']}"},
    disable_batch=True,   # 데모·개발용: 즉시 전송 (운영은 9장 참고)
)

# 이 아래에서 LLM SDK / LangChain import
from anthropic import Anthropic

앱 로그에 Traceloop exporting traces to https://...가 보이면 연결 설정은 끝난 것입니다.

④ (선택) 업무 단위 묶기

python
from traceloop.sdk.decorators import workflow, task

@task(name="retrieve_docs")
def retrieve(q): ...

@workflow(name="answer_question")

    docs = retrieve(q)
    return llm_call(q, docs)

3-1. Node.js 앱에 적용

@traceloop/node-server-sdk를 씁니다. Dynatrace 문서 기준으로 Node.js SDK는 Metric을 지원하지 않아 Trace만 수집됩니다(Token 수는 Span 속성으로 남음).

① 설치

bash
npm install @traceloop/node-server-sdk

② 초기화 코드 (엔트리 파일 맨 위, LLM SDK보다 먼저)

javascript

import * as traceloop from "@traceloop/node-server-sdk";

traceloop.initialize({
  appName: "my-ai-app",
  baseUrl: `${process.env.DT_ENDPOINT}/api/v2/otlp`,
  headers: { Authorization: `Api-Token ${process.env.DT_TOKEN}` },
  disableBatch: true,        // 데모·개발용 (운영은 false)
  traceContent: true,        // 운영에서 프롬프트 원문을 남기지 않으려면 false
});

// index.js
import "./tracing.js";                    // 반드시 첫 줄
import Anthropic from "@anthropic-ai/sdk"; // 그 다음 LLM SDK

③ ESM · 번들러 환경

Next.js·webpack처럼 import 순서를 보장하기 어려우면 instrumentModules로 모듈을 직접 넘깁니다.

import OpenAI from "openai";

5. Agent·Tool을 Agents topology에 보이게 하기

자동 계측만으로는 Agents topology의 Agents가 0으로 나올 수 있습니다. Dynatrace는 OpenTelemetry GenAI agent semantic conventions(gen_ai.operation.name=invoke_agent, gen_ai.agent.name)이 있는 Span을 Agent로 인식하는데, traceloop-sdk 0.50.1의 LangChain 계측은 AgentExecutor를 workflow Span으로만 남기기 때문입니다.

① Agent 실행을 @agent로 감싸고 표준 속성 추가

python
from opentelemetry import trace
from traceloop.sdk.decorators import agent

AGENT_NAME = "travel-advisor-agent"

@agent(name=AGENT_NAME)   # 하위 LLM·Tool Span에도 gen_ai.agent.name 자동 전파
def run_agent(task: str):
    span = trace.get_current_span()
    span.set_attribute("gen_ai.operation.name", "invoke_agent")
    span.set_attribute("gen_ai.agent.name", AGENT_NAME)
    span.set_attribute("gen_ai.agent.id", "travel-advisor-agent-v1")
    span.set_attribute("gen_ai.agent.description", "Validates the city and gives travel advice")
    span.set_attribute("gen_ai.provider.name", "anthropic")      # aws.bedrock, openai ...
    span.set_attribute("gen_ai.request.model", "claude-haiku-4-5-20251001")
    return agent_executor.invoke({"input": task})

② Tool 함수에 execute_tool 속성 추가

python
def mark_tool_span(name: str, description: str) -> None:
    span = trace.get_current_span()          # LangChain이 만든 Tool Span
    span.set_attribute("gen_ai.operation.name", "execute_tool")
    span.set_attribute("gen_ai.tool.name", name)
    span.set_attribute("gen_ai.tool.type", "function")
    span.set_attribute("gen_ai.tool.description", description)

@tool
def valid_city(city: str) -> bool:
    """Returns if the input is a valid city"""
    mark_tool_span("valid_city", "Returns if the input is a valid city")
    ...
OpenAI Agents SDK, CrewAI처럼 Agent 전용 계측이 있는 프레임워크는 이 작업이 필요 없을 수 있습니다. 먼저 Agents topology를 확인하고 0일 때만 추가하세요.

7. 적용 검증

요청을 2~3번 보낸 뒤 1~2분 기다렸다가 아래 순서로 확인합니다.

  1. 앱 로그: Traceloop exporting traces to https://... 확인, Illegal header key 오류 없음
  2. Distributed Tracing: 서비스 선택 → LLM Span의 gen_ai.request.model, Token 속성 확인
  3. AI Observability: Overview의 Model·Provider, Agents topology의 연결 확인
  4. Notebooks(DQL): 아래 쿼리로 수치 확인

Model별 요청 수 · Token · 지연 시간

DQL
fetch spans, from: now() - 1h
| filter isNotNull(gen_ai.request.model)
| summarize requests = count(),
            input_tokens = sum(gen_ai.usage.input_tokens),
            output_tokens = sum(gen_ai.usage.output_tokens),
            p95 = percentile(duration, 95),
            by: { service.name, gen_ai.request.model }

Agent 실행 횟수와 소요 시간

DQL
fetch spans, from: now() - 1h
| filter gen_ai.operation.name == "invoke_agent"
| summarize runs = count(), avg_duration = avg(duration), by: { gen_ai.agent.name }

Tool별 호출 횟수

DQL
fetch spans, from: now() - 1h
| filter gen_ai.operation.name == "execute_tool"
| summarize calls = count(), by: { gen_ai.agent.name, gen_ai.tool.name }

실패한 LLM 호출

DQL
fetch spans, from: now() - 1h
| filter isNotNull(gen_ai.system) and span.status_code == "error"
| fields start_time, service.name, span.name, gen_ai.request.model
| sort start_time desc

Token 속성이 문자열로 들어오면 toLong()으로 감싸 합계를 구하세요.
